## 1 三条铁律

1. **角色从 token 来，不从请求体来。** 前端传 `role`、`doctorId`、`patientId` 一律忽略。
2. **归属必须落在查询条件里。** 不能先 `findById` 再在内存里 `if` 判断；要用 `findByIdAndPatientId` / `findByIdAndDoctorId`，查不到就是 404。
3. **状态校验放在领域对象里。** Controller 的 `@PreAuthorize` 只挡角色；「当前状态能不能审方」必须由 `PrescriptionStateMachine` 判断，避免多个入口绕过。

## 2 角色

| 角色 | 编码 | 数据范围 | 典型入口 |
|---|---|---|---|
| 患者 | `PATIENT` | 自己的订单、消息、处方 | 患者端 |
| 医生 | `DOCTOR` | 自己接诊的订单、自己开的处方 | 医生工作台 |
| 药师 | `PHARMACIST` | 待审处方、待核销处方 | 药师工作台 |
| 管理员 | `ADMIN` | 全部数据（临床内容只读） | 管理后台 |
| 系统 | `SYSTEM` | 定时任务：订单超时关闭、处方过期作废 | 无登录入口 |

> `SYSTEM` 不是登录角色，只用于定时任务与审计日志的 `actor`。

## 5 数据归属

### 5.1 患者

```sql
-- 列表
SELECT ... FROM consultation_order
WHERE patient_id = #{currentUserId}
  AND (#{status} IS NULL OR status = #{status})
ORDER BY created_at DESC
LIMIT #{offset}, #{size};

-- 详情：查不到就是 404，不区分「不存在」与「不是你的」
SELECT ... FROM consultation_order
WHERE id = #{id} AND patient_id = #{currentUserId};
```

处方同理：`prescription.patient_id = currentUserId`。

### 5.2 医生

```sql
SELECT ... FROM consultation_order
WHERE doctor_id = #{currentDoctorId}
  AND status = #{status};
```

`currentDoctorId` 的获得：

```java
// 登录用户 userId -> doctor 表
Long doctorId = doctorQueryPort.findDoctorIdByUserId(currentUser.userId())
    .orElseThrow(() -> new BizException(ErrorCode.FORBIDDEN));
```

不允许前端传 `doctorId`；医生账号未绑定医生记录时，调用业务接口返回 403。

### 5.3 药师

```sql
-- 待审队列
SELECT ... FROM prescription
WHERE status = 'PENDING_REVIEW'
ORDER BY submitted_at ASC;

-- 待核销
SELECT ... FROM prescription
WHERE status = 'CIRCULATED' AND valid_until >= NOW(3);
```

药师不需要「归属」，但只能看到与审方/核销相关的字段；患者手机号、地址等不返回。

### 5.4 管理员

- 全部数据可查；
- 不能修改诊断、药品明细、审方结论；
- 强制作废必须填理由，必须写 `audit_log`；
- 查询审计日志本身也要写一条审计（谁在什么时候查了什么）。

## 6 状态机权限

### 6.1 处方

| 迁移 | 动作 | 角色 | 前置条件 | 失败 |
|---|---|---|---|---|
| T1 | 提交审核 | 医生（开方人） | `DRAFT`/`REJECTED`；诊断非空；明细 1–5；药品启用；version 匹配 | 400/404/409 |
| T2 | 审核通过 | 药师 | `PENDING_REVIEW`；version 匹配 | 404/409 |
| T3 | 审核驳回 | 药师 | `PENDING_REVIEW`；理由 ≥10 字；version 匹配 | 400/409 |
| T4 | 修改后重提 | 医生（开方人） | `REJECTED`；满足 T1；version 匹配 | 400/404/409 |
| T5 | 作废草稿 | 医生（开方人） | `DRAFT`；理由；version 匹配 | 400/409 |
| T6 | 核销 | 药师 | `CIRCULATED`；`now <= validUntil`；version 匹配 | 409 |
| T7 | 过期作废 | SYSTEM | `CIRCULATED`；`now > validUntil` | — |
| T8 | 强制作废 | ADMIN | `PENDING_REVIEW`；理由；version 匹配 | 400/409 |

### 6.2 订单

| 迁移 | 动作 | 角色 | 前置条件 |
|---|---|---|---|
| O1 | 创建 | 患者 | 医生存在且启用；描述 10–500 字 |
| O2 | 支付 | 患者（本人） | `PENDING_PAYMENT`；未超 30 分钟 |
| O3 | 接诊 | 医生（本人） | `PENDING_ACCEPT` |
| O4 | 拒诊 | 医生（本人） | `PENDING_ACCEPT`；理由 ≥5 字 |
| O5 | 结束 | 医生（本人） | `IN_CONSULTATION`；有已流转/已核销处方，或 `noPrescription=true` |
| O6 | 超时关闭 | SYSTEM | `PENDING_PAYMENT` 超过 30 分钟 |
| O7 | 患者取消 | 患者（本人） | `PENDING_PAYMENT` |

## 7 401 / 403 / 404 / 409

| 场景 | 返回 | 业务码 | 前端 |
|---|---|---|---|
| 无 token / token 过期 | 401 | 40101 | 清 token，跳登录 |
| 角色不允许（患者调审方） | 403 | 40301 | 无权限提示 |
| 资源不存在 | 404 | 40401 | 未找到 |
| 资源不属于当前用户 | 404 | 40401 | 未找到（与上一条一致） |
| 状态不允许 | 409 | 40901 | 刷新详情，提示当前状态 |
| version 冲突 | 409 | 40902 | 刷新详情，重试 |
| 重复操作 | 409 | 40903 | 提示已处理 |

**为什么「不属于你」也返回 404？**
如果「存在但无权」返回 403、「不存在」返回 404，攻击者可以用 403/404 的差异枚举资源 ID。统一 404 可以隐藏资源存在性。代价是前端无法区分「没权限」和「没数据」，但这两者对用户都表现为「看不到」。

**角色不允许为什么返回 403，而不是 404？**
因为接口本身是公开存在的（例如 `/prescriptions/{id}/approve` 就是审方接口），隐藏接口没有意义；此时 403 是准确的语义。

## 8 实现骨架

### 8.1 Spring Security 配置

```java
@Configuration
@EnableMethodSecurity
public class SecurityConfig {

    @Bean
    SecurityFilterChain filterChain(HttpSecurity http, JwtAuthenticationFilter jwtFilter)
            throws Exception {
        http.csrf(AbstractHttpConfigurer::disable)
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/auth/register", "/api/v1/auth/login").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .exceptionHandling(e -> e
                .authenticationEntryPoint((req, res, ex) ->
                    writeError(res, 401, ErrorCode.UNAUTHORIZED))
                .accessDeniedHandler((req, res, ex) ->
                    writeError(res, 403, ErrorCode.FORBIDDEN)));
        return http.build();
    }
}
```

### 8.2 Controller：只挡角色

```java
@RestController
@RequestMapping("/api/v1/prescriptions")
public class PrescriptionController {

    @PostMapping("/{id}/approve")
    @PreAuthorize("hasRole('PHARMACIST')")
    public ApiResponse<PrescriptionVO> approve(
            @PathVariable Long id,
            @RequestBody @Valid VersionRequest req,
            @AuthenticationPrincipal CurrentUser user) {
        return ApiResponse.ok(service.approve(id, user, req.version()));
    }
}
```

### 8.3 Application：归属 + 状态

```java
@Transactional
public PrescriptionVO approve(Long id, CurrentUser user, int version) {
    Prescription p = repository.findById(id)
        .orElseThrow(() -> new BizException(ErrorCode.NOT_FOUND));

    p.approve(user.userId(), version); // 内部校验状态、version，失败抛 409
    repository.save(p);
    reviewRepository.save(ReviewRecord.approved(p, user.userId()));
    auditRecorder.record(AuditAction.PRESCRIPTION_APPROVE, p, user);
    events.publishEvent(new PrescriptionCirculatedEvent(p.id()));
    return assembler.toVO(p);
}
```

医生侧：

```java
@Transactional
public PrescriptionVO update(Long id, CurrentUser user, UpdatePrescriptionRequest req) {
    Prescription p = repository.findByIdAndDoctorId(id, currentDoctorId(user))
        .orElseThrow(() -> new BizException(ErrorCode.NOT_FOUND));
    p.update(req, user.userId()); // DRAFT/REJECTED 才能改
    repository.save(p);
    return assembler.toVO(p);
}
```

### 8.4 领域状态机

```java
public void approve(Long pharmacistId, int expectedVersion) {
    if (status != PENDING_REVIEW) {
        throw new BizException(ErrorCode.STATE_CONFLICT, status);
    }
    if (version != expectedVersion) {
        throw new BizException(ErrorCode.VERSION_CONFLICT, status, version);
    }
    this.status = CIRCULATED;
    this.validUntil = LocalDateTime.now().plusDays(3);
    this.version++;
    this.reviewedBy = pharmacistId;
    this.reviewedAt = LocalDateTime.now();
}
```

> 真正的并发安全还要求 `UPDATE ... WHERE version=?`；仅在内存里比 `version` 不够。

## 10 PR 审查清单（权限部分）

- [ ] 新接口在矩阵中有登记？
- [ ] `@PreAuthorize` 角色与矩阵一致？
- [ ] 是否从 `CurrentUser` 取 `userId/role`，没有信任请求体？
- [ ] 查询是否带 `patient_id` / `doctor_id` 条件？
- [ ] 状态迁移是否走领域状态机？是否带 `version`？
- [ ] 401/403/404/409 是否按表返回？
- [ ] 审方、核销、强制作废、账号启停是否写审计？
- [ ] 是否新增/更新了 SEC 测试用例？
- [ ] 日志是否打印了 token、密码、完整手机号？
- [ ] 前端是否只是隐藏按钮，而没有把权限判断当安全边界？
