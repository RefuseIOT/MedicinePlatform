# docs/02-design 索引

本目录是 S0～S4 的架构、接口、权限基线。写代码前先看这里，改接口先改这里。

| 文件 | 解决什么问题 | 主要读者 |
|---|---|---|
| `系统设计规格说明书.md` | 架构选型、分层、模块边界、依赖规则、物理架构、接口与权限总览 | 全组；老师看设计章节 |
| `API接口规范.md` | 前后端契约：路径、字段、错误码、分页、关键示例 | 4号前端、5号后端、6号接口测试 |
| `权限矩阵.md` | 角色、权限码、接口矩阵、数据归属、状态机权限、测试用例 | 5号后端、6号测试、2号 review |
| `PR审查清单.md` | 每次 PR 的 10 分钟检查表 | 全组 review |

## 建议阅读顺序

1. 先读 `系统设计规格说明书.md` 的 3、4 章：知道为什么是模块化单体、六个模块怎么分。
2. 再读 5、6 章：知道接口怎么约定、错误码怎么返回。
3. 写代码前读 `权限矩阵.md` 的 4、5、6 节：知道自己模块的接口要让谁过、查什么条件、什么状态才能操作。
4. 提 PR 前读 `PR审查清单.md`：自己先过一遍，减少 review 往返。

## 维护规则

- 任何接口字段/路径/错误码变化，先改 `API接口规范.md`，再改代码；
- 任何新接口，先在 `权限矩阵.md` 加一行，再写 Controller；
- 任何模块边界/依赖变化，先改 `系统设计规格说明书.md` 的 3、4 章，并在 PR 描述里说明；
- 2号负责合并前检查「文档—代码—前端调用」三处一致；
- 文档版本与 Sprint 对应：S0 基线 v0.1，S1 评审后升 v0.2，以此类推。
